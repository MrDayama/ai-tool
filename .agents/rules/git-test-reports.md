# 📜 ルール: テスト結果の Git リポジトリ同期 ＆ プロジェクト識別・標準テンプレート仕様

今後、機能改修・改善・テスト検証を行った際は、単体ファイルのみを外部へ移動・アーカイブした場合でも**どのプロジェクト・リポジトリ・バージョン・機能のテスト結果であるかが一目で識別できる標準構成仕様**に従い、自動生成して Git リポジトリへ同調コミット＆全ブランチ同期プッシュを行うこと。

---

## 🏢 1. プロジェクト識別構成仕様 (Project Identification Specification)

テスト報告書単体で「何のアプリ・どのバージョン・どのコミット」の検証結果か一視で識別可能にするため、以下のメタデータ項目をすべての報告書・ファイル命名に組み込むこと。

### 🏷️ **A. 共通ファイル命名規則 (File Naming Convention)**
```text
[プロジェクト名]_[機能サブ名]_[テスト報告種別]_[バージョン/キャッシュバスター].[拡張子]
```
- 例: `ai-tool_poker-memo_Test_Report_v20260901_30000.xlsx`
- 例: `ai-tool_poker-memo_Test_Report_v20260901_30000.pdf`

### 🏢 **B. 必須プロジェクト識別メタデータヘッダー (Project Header Block)**
報告書（Excelのサマリーシート・詳細シート、PDFの表紙、Markdown仕様書）の最上部・概要枠に以下の8項目を必ず常時表示すること：
1. **プロジェクト名 (Project Name)**: 例 `ai-tool`
2. **対象サービス / アプリ名**: 例 `Poker Memo Web (ポーカー手札メモ＆リプレイツール)`
3. **対象リポジトリ URI**: 例 `https://github.com/MrDayama/ai-tool`
4. **対象ブランチ ＆ コミットID**: 例 `main / gh-pages (Commit: 431dd63)`
5. **アプリバージョン / バスター**: 例 `v20260901_30000`
6. **動作検証本番 URL**: 例 `https://mrdayama.github.io/ai-tool/`
7. **テスト実施日時**: 例 `2026年9月1日 17:00:00 (JST)`
8. **検証環境 / ブラウザ**: 例 `Windows / Chromium Headless (Playwright v1.50)`

## 📋 2. テスト結果報告書フォーマット標準仕様 (Excel / PDF)

### 📊 **シート1: `📊 総合サマリー` (Overall Dashboard)**
- 上記 **🏢 プロジェクト識別メタデータヘッダー** を最上部に常時表示。
- **総合判定**: 全テストケース数、PASS件数、FAIL件数、総合パス率 (%)
- **テストケース一覧 ＆ 各シートインデックス**:  
  全ケースの テストID、対象機能名、対応する個別シート名、重要度 (High/Medium/Low)、判定結果 (`PASS`/`FAIL`) の対比一覧。

### 🧪 **シート2～N: `TC-XX_ケース名` (個別ケース詳細 ＆ スクリーンショット埋め込み)**
各テストケースごとに**独立したシート**を作成し、以下を一括掲載する：
1. **プロジェクト識別ヘッダー**: プロジェクト名 (`ai-tool`) ＆ テストID
2. **基本情報**: テストケース名、前提条件、重要度、判定結果 (`PASS` は緑背景太字)
3. **実行内容**: 実行手順 (Step 1, 2, 3...)、期待されるシステム結果、実際の結果（実測値）
4. **📸 エビデンス画像 (スクリーンショット直接埋め込み)**:  
   テスト実行時に自動撮影されたハイレゾキャプチャ画像を**シート上の B13 セル位置へ直接画像埋め込み**（幅480px前後で自動アライメント）し、スクロールせずに結果を一目で視覚確認できるように集約配置する。

## 🚀 3. Git リポジトリ同期 ＆ 運用フロー

1. **資料の自動作成**:
   - 上記フォーマットに準拠した Excel 報告書 (`ai-tool_poker-memo_Test_Report_v20260901_30000.xlsx`)
   - 印刷・PDF閲覧用報告書 (`ai-tool_poker-memo_Test_Report_v20260901_30000.pdf`)
   - テストエビデンス画像一式 (`test_tc*.jpg`)
   - テスト仕様書 (`test_specification.md`)

2. **Git リポジトリ (`docs/test-reports/[プロジェクトID]/[バージョン名]/`) への階層化同期配備**:
   - 生成資料一式を `docs/test-reports/ai-tool/v20260901_30000/` へ配備する。
   - `git add docs/test-reports/` を実行。

3. **全追跡ブランチへの強合同期**:
   - `main`, `gh-pages`, `dev`, `ai-dev`, `deploy-timebomb` へプッシュし、GitHub 側で即座にエビデンスをオンライン閲覧可能な状態を維持する。

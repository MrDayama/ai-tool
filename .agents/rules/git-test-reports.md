# 📜 ルール: テスト結果の Git リポジトリ同期 ＆ 標準フォーマットテンプレート仕様

今後、機能改修・改善・テスト検証を行った際は、以下の標準フォーマット仕様および手順に**必ず従って**自動生成し、Git リポジトリへ同調コミット＆全ブランチ同期プッシュを行うこと。

---

## 📋 1. テスト結果報告書フォーマット標準仕様 (Excel / PDF)

テスト結果の可読性・確認しやすさを最大化するため、成果物ファイルは以下の**構造化テンプレート構成**で作成・集約すること。

### 📊 **シート1: `📊 総合サマリー` (Overall Dashboard)**
- **プロジェクト基本情報**: 対象システム名、機能名、テスト実施日、検証環境（OS/ブラウザ/URL）
- **総合判定**: 全テストケース数、PASS件数、FAIL件数、総合パス率 (%)
- **テストケース一覧 ＆ 各シートインデックス**:  
  全ケースの テストID、対象機能名、対応する個別シート名、重要度 (High/Medium/Low)、判定結果 (`PASS`/`FAIL`) の対比一覧。

### 🧪 **シート2～N: `TC-XX_ケース名` (個別ケース詳細 ＆ スクリーンショット埋め込み)**
各テストケースごとに**独立したシート**（または構造化セクション）を作成し、以下を一括掲載する：
1. **ケースヘッダー**: テストID、重要度、判定結果 (`PASS` は緑背景太字)
2. **基本仕様**: テストケース名、前提条件
3. **実行内容**: 実行手順 (Step 1, 2, 3...)、期待されるシステム結果、実際の結果（実測値）
4. **📸 エビデンス画像 (スクリーンショット直接埋め込み)**:  
   テスト実行時に自動撮影されたハイレゾキャプチャ画像を**シート上の B13 セル位置へ直接画像埋め込み**（幅480px前後で自動アライメント）し、スクロールせずに結果を一目で視覚確認できるように集約配置する。

---

## 🚀 2. Git リポジトリ同期 ＆ 運用フロー

1. **資料の自動作成**:
   - 上記フォーマットに準拠した Excel 報告書 (`Poker_Memo_Test_Report_V2.xlsx`)
   - 印刷・PDF閲覧用報告書 (`Poker_Memo_Test_Report.pdf`)
   - テストエビデンス画像一式 (`test_tc*.jpg`)
   - テスト仕様書 (`test_specification.md`)

2. **Git リポジトリ (`docs/test-reports/`) への同期配備**:
   - 生成資料一式を `docs/test-reports/` へ配備する。
   - `git add docs/test-reports/` を実行。

3. **全追跡ブランチへの強合同期**:
   - `main`, `gh-pages`, `dev`, `ai-dev`, `deploy-timebomb` へプッシュし、GitHub 側で即座にエビデンスをオンライン閲覧可能な状態を維持する。
